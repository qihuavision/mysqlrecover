# 企业微信通知模板设计

> FP-07：演练结束后，向企业微信群发送摘要通知。
> 设计原则：**简短、关键信息齐全、附报告链接、失败醒目**。
> 最后更新：2026-08-13

---

## 触发时机

每次 `drill run` 批次完成后（无论成功/部分失败/全部失败）发送一次通知。

---

## 通知格式：Markdown 类型

企业微信支持 Markdown 消息类型，渲染效果比纯文本好。用 Markdown 格式。

### 成功通知模板

```markdown
### ✅ MySQL 恢复演练完成

**批次**：#42
**目标机**：10.0.1.50
**时间**：2026-08-13 14:30 ~ 15:12（耗时 42 分钟）

**结果汇总**：
> 总数：**100**　成功：**98**　失败：**2**
> 成功率：**98.0%**

**失败实例**：
- ❌ `order-db-prod-03`（8.0.35）— 容器启动失败，详见 error 日志
- ❌ `log-db-slave-07`（5.7.44）— 验证失败 COUNT=0，已重试1次

📄 [查看完整报告](http://管理机IP:8080/report/42)
```

### 全部成功通知模板（简化版）

```markdown
### ✅ MySQL 恢复演练完成

**批次**：#42 | **目标机**：10.0.1.50 | **耗时**：42 分钟
**结果**：100/100 全部成功 🎉
📄 [查看完整报告](http://管理机IP:8080/report/42)
```

### 启动失败/异常终止通知模板

```markdown
### 🔴 MySQL 恢复演练异常终止

**批次**：#42
**目标机**：10.0.1.50
**状态**：**ABORTED**
**原因**：恢复机磁盘不足（剩余 2GB，需至少 50GB）
**已完成**：15/100（成功 12，失败 3）

⚠️ 请 DBA 检查恢复机磁盘后重跑：
`toolkit drill run --target 10.0.1.50 --all --yes`
```

## 通知内容字段映射

| 通知字段 | 数据来源 |
|---|---|
| 批次号 | `drill_runs.id` |
| 目标机 | `drill_runs.target_host` |
| 时间 | `drill_runs.started_at` / `finished_at` / `duration_sec` |
| 总数/成功/失败 | `drill_runs.total_count` / `success_count` / `failed_count` |
| 失败实例明细 | `recovery_tasks` 中 status=FAILED_FINAL 的记录 |
| 失败原因 | `recovery_tasks.error_msg` |
| 报告链接 | Web UI 地址（FP-09，Sprint 4） |

## 企业微信 webhook 调用

```python
# notifiers/wecom.py 核心逻辑
import requests

def send_wecom(webhook_url: str, markdown_content: str) -> bool:
    """发送企业微信 Markdown 消息。失败重试 3 次，不阻塞主流程。"""
    payload = {
        "msgtype": "markdown",
        "markdown": {"content": markdown_content}
    }
    for attempt in range(3):
        try:
            resp = requests.post(webhook_url, json=payload, timeout=10)
            if resp.json().get("errcode") == 0:
                return True
        except Exception:
            continue
    return False  # 3 次失败，记录日志，不阻塞主流程
```

**异常处理**（FP-07）：webhook 发送失败重试 3 次，仍失败只记录日志，**不阻塞主流程**（演练结果已入库，通知只是辅助）。

## 配置

```yaml
# config/config.yaml
notifier:
  wecom:
    enabled: true
    webhook_url: "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx"
    # 通知时机：always（默认）/ on_failure（仅失败时通知）
    notify_on: always
```

## 失败实例的描述规则

通知里"失败实例"部分，按 `error_msg` 自动归类描述：

| 错误类型 | 描述模板 |
|---|---|
| 容器启动失败 | `容器启动失败，详见 error 日志` |
| 验证 COUNT=0 | `验证失败 COUNT=0，已重试1次` |
| 无业务库（不应该 FAIL，但兜底） | `无业务库可验证` |
| xtrabackup prepare 失败 | `备份 prepare 失败：{错误片段}` |
| copy-back 失败 | `数据恢复失败：{错误片段}` |
| SSH 不通 | `恢复机/备份源机 SSH 不通` |
| 磁盘不足 | `磁盘空间不足` |

> 失败实例超过 5 个时，通知里只列前 5 个 + "等共 N 个失败，详见报告"。

## 扩展性

`notifiers/` 设计为插件式（ADR-07 抽象基类），后续可加：
- 钉钉通知（`notifiers/dingtalk.py`）
- 邮件通知（`notifiers/email.py`）
- Slack 通知（`notifiers/slack.py`）

只需实现 `BaseNotifier.send()` 接口，配置里切换即可。
