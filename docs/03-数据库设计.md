# 元数据库设计

> 工具自身的状态库，持久化实例/备份/任务/容器记录，支持崩溃续跑与审计。
> **选型：SQLite**（ADR-03），**设计兼容 MySQL，可无痛迁移**（见末尾迁移指南）。
> 最后更新：2026-08-13（适配 ADR-08/09/10）

---

## 设计规范

为保障 SQLite → MySQL 无痛迁移，遵守以下纪律：

1. **用 SQLAlchemy ORM 定义模型**，不手写裸 SQL 建表。切换 MySQL 仅改连接串。
2. **字段用 MySQL 兼容类型**：`VARCHAR(n)` / `INT` / `DATETIME` / `TEXT` / `INTEGER(0/1)`。
3. **时间统一存 ISO8601 字符串**（如 `2026-08-13T14:30:00`），由 Python 应用层生成，不用数据库时间函数。
4. **JSON 字段存 TEXT**，应用层 `json.dumps/loads`。
5. **避免 SQLite 方言特性**：不用 `WITHOUT ROWID` / `PRAGMA` 特有功能 / `RETURNING` 语法。
6. **主键统一** `id INT AUTO_INCREMENT PRIMARY KEY`（ORM 层 `Integer, primary_key=True`）。
7. **所有表加 `created_at` / `updated_at`** 审计字段。

## 表结构

### mysql_containers（MySQL 常驻容器池 · ADR-09）

> 记录恢复机上每个版本的常驻 Docker 容器。每个版本一个容器，端口固定 13306。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INT | PK, AUTO_INCREMENT | |
| mysql_version | VARCHAR(20) | NOT NULL, UNIQUE | 如 `8.0.35`、`5.7.44` |
| container_name | VARCHAR(64) | NOT NULL | 如 `drill-mysql-8035` |
| docker_image | VARCHAR(128) | NOT NULL | 如 `mysql:8.0.35` |
| datadir_path | VARCHAR(256) | NOT NULL | 宿主机挂载路径 `/data/drill/8.0.35/datadir` |
| drill_port | INT | NOT NULL, DEFAULT 13306 | 固定端口（串行复用，ADR-09） |
| status | VARCHAR(20) | NOT NULL, DEFAULT 'created' | created/running/stopped/error |
| created_at | DATETIME | NOT NULL | |
| updated_at | DATETIME | NOT NULL | |

**索引**：
- `UNIQUE INDEX idx_version (mysql_version)` —— 一个版本一个容器
- `INDEX idx_status (status)` —— 快速查"当前 running 的容器"

---

### instances（源生产实例清单）

> 对应 `config/instances.yaml` 里的实例，启动时同步入库。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INT | PK, AUTO_INCREMENT | |
| name | VARCHAR(64) | NOT NULL | 实例名（人类可读，如 `order-db-prod-01`） |
| host | VARCHAR(64) | NOT NULL | 源实例 IP |
| port | INT | NOT NULL, DEFAULT 3306 | |
| mysql_version | VARCHAR(20) | NOT NULL | 如 `8.0.35` |
| backup_source_host | VARCHAR(64) | NOT NULL | 备份归档所在机器 IP |
| backup_source_path | VARCHAR(256) | NOT NULL | 备份归档目录 |
| enabled | INTEGER | NOT NULL, DEFAULT 1 | 0/1 是否纳入演练 |
| created_at | DATETIME | NOT NULL | |
| updated_at | DATETIME | NOT NULL | |

> 📌 **ADR-10 变更**：移除了原设计的 `verify_db / verify_table / verify_min_rows` 字段 —— 验证改为自动发现（ADR-10），无需 per-instance 配置。
> 📌 密码不入库（ADR-10 环境变量方案）。

**索引**：
- `UNIQUE INDEX idx_name (name)` —— 实例名唯一
- `INDEX idx_enabled (enabled)` —— 快速筛选启用的实例
- `INDEX idx_version (mysql_version)` —— 按版本排序恢复（ADR-09 同版本连续）

### backups（备份记录）

> 登记从备份源机扫描到的可用备份。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INT | PK, AUTO_INCREMENT | |
| instance_id | INT | NOT NULL, FK → instances.id | |
| backup_path | VARCHAR(512) | NOT NULL | 备份在源机上的完整路径 |
| backup_type | VARCHAR(10) | NOT NULL, DEFAULT 'full' | full / incr（本期仅 full） |
| size_bytes | BIGINT | | 备份大小（字节） |
| xtrabackup_version | VARCHAR(20) | | 备份所用 xtrabackup 版本 |
| status | VARCHAR(20) | NOT NULL, DEFAULT 'available' | available/corrupt/missing/consumed |
| started_at | DATETIME | | 备份开始时间（从 xtrabackup_info 读） |
| finished_at | DATETIME | | 备份完成时间 |
| discovered_at | DATETIME | NOT NULL | 工具登记时间 |
| created_at | DATETIME | NOT NULL | |
| updated_at | DATETIME | NOT NULL | |

**索引**：
- `INDEX idx_backup_instance_time (instance_id, finished_at DESC)` —— 查某实例最新备份
- `INDEX idx_backup_status (status)` —— 筛选可用备份

| status | VARCHAR(20) | NOT NULL, DEFAULT 'running' | running/completed/aborted |
| started_at | DATETIME | NOT NULL | |
| finished_at | DATETIME | | |
| duration_sec | INT | | |
| created_at | DATETIME | NOT NULL | |

**索引**：
- `INDEX idx_run_status (status)` —— 查进行中的批次
- `INDEX idx_run_started (started_at DESC)` —— 按时间排历史

### recovery_tasks（恢复任务）

> 每个实例的每次恢复是一个任务。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INT | PK, AUTO_INCREMENT | |
| run_id | INT | NOT NULL, FK → drill_runs.id | 所属批次 |
| instance_id | INT | NOT NULL, FK → instances.id | |
| backup_id | INT | NOT NULL, FK → backups.id | |
| container_name | VARCHAR(64) | NOT NULL | 用的常驻容器（ADR-09） |
| status | VARCHAR(20) | NOT NULL, DEFAULT 'PENDING' | 见状态机 |
| attempt | INT | NOT NULL, DEFAULT 1 | 尝试次数（1 或 2，ADR 重试1次） |
| started_at | DATETIME | | |
| finished_at | DATETIME | | |
| duration_sec | INT | | |
| error_msg | TEXT | | 失败原因 |
| verify_db | VARCHAR(64) | | 自动发现选中的验证库（诊断用） |
| verify_table | VARCHAR(64) | | 自动发现选中的验证表（诊断用） |
| verify_count | BIGINT | | COUNT(*) 结果（诊断用） |
| created_at | DATETIME | NOT NULL | |
| updated_at | DATETIME | NOT NULL | |

**任务状态机**（ADR-05/10）：
```
PENDING → RUNNING → SUCCESS
                  → FAILED → RETRYING → SUCCESS
                                       → FAILED_FINAL
```

**索引**：
- `INDEX idx_task_run (run_id, status)` —— 批次内任务状态汇总
- `INDEX idx_task_instance (instance_id)` —— 某实例历史
- `INDEX idx_task_status (status)` —— 查 PENDING/RETRYING 任务（断点续跑）

### recovery_logs（验证与错误日志归档索引）

> ADR-10 要求：启动失败时采集 docker logs + MySQL error log 并归档。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INT | PK, AUTO_INCREMENT | |
| task_id | INT | NOT NULL, FK → recovery_tasks.id | |
| log_dir | VARCHAR(512) | NOT NULL | 归档根目录 `/归档/YYYY-MM-DD/{IP}_{版本}/` |
| xb_log_path | VARCHAR(512) | | xtrabackup prepare/copy-back 日志 |
| verify_log_path | VARCHAR(512) | | 验证过程日志 |

| docker_log_path | VARCHAR(512) | | `docker logs` 输出（ADR-10） |
| created_at | DATETIME | NOT NULL | |

**索引**：
- `INDEX idx_log_task (task_id)` —— 查某任务的日志

## 索引规范总结

| 规范 | 说明 |
|---|---|
| 主键 | 所有表 `id INT AUTO_INCREMENT PRIMARY KEY` |
| 唯一约束 | 业务唯一字段加 UNIQUE（如 mysql_version、instance name） |
| 外键查询字段 | 加普通 INDEX（instance_id、backup_id、run_id、task_id） |
| 状态筛选字段 | 加 INDEX（status、enabled） |
| 时间排序字段 | 加 INDEX（started_at、finished_at DESC） |
| 复合索引 | 高频组合查询建复合索引（如 `instance_id + finished_at`） |

---

## 保留策略

- `recovery_tasks` + `recovery_logs`：默认保留 **6 个月**（等保审计要求）
- `drill_runs`：永久保留（批次历史，体积小）
- `backups`：跟随源机备份实际存在性，扫描时自动标记 missing
- 超期清理脚本（Sprint 4）单独实现，配置保留天数

## SQLite → MySQL 迁移指南

当数据量增大或需要多管理机共享元数据时，迁移到 MySQL：

### 步骤

1. **改连接串**（`config.yaml`）：
   ```yaml
   # SQLite
   database:
     url: sqlite:///data/toolkit.db
   
   # MySQL
   database:
     url: mysql+pymysql://user:pass@mysql-host:3306/toolkit?charset=utf8mb4
   ```

2. **建表**（ORM 自动适配方言）：
   ```python
   # 无需改模型代码，SQLAlchemy 自动生成 MySQL DDL
   Base.metadata.create_all(mysql_engine)
   ```

3. **数据迁移**（二选一）：
   - **小数据量**：用 SQLiteStudio / `sqlite3 .dump` 导出 SQL，替换类型后导入 MySQL
   - **推荐**：写一个 Python 脚本，用 ORM 同时读 SQLite 写 MySQL（最稳）

### 迁移无痛的保障

正因为遵守了开头"设计规范"的 7 条纪律，迁移时**无需改任何模型代码**，只改连接串 + 建表 + 导数据。这正是选 SQLAlchemy ORM 的核心价值。
