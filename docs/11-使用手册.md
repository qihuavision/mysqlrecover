## 1. 工具简介

**解决什么问题**：上百个 MySQL 实例的 xtrabackup 备份，需要定期恢复演练验证可用性。手动流程：每台装 MySQL → 恢复 → 登录验证 → 循环上百次。

**本工具**：一条命令完成全部 —— 自动管理多版本 MySQL（Docker 容器池）→ 按版本排队恢复 → 自动发现业务库验证 → 失败重试 → 断点续跑。

```
一条命令：
toolkit drill run --target <恢复机IP> --all --yes
```

## 2. 架构一览

```
┌─────────────────────┐         ┌──────────────────────────────┐
│  管理机（跑工具）    │  SSH    │  恢复机（一台空服务器即可）    │
│  Windows / Linux    │ ──────▶ │                              │
│                     │         │  Docker                      │
│  · toolkit CLI      │         │   ├─ drill-mysql-8035 (8.0)  │
│  · SQLite 元数据    │         │   └─ drill-mysql-5744 (5.7)  │
│  · 备份源机配置     │         │  xtrabackup（宿主机）         │
└─────────────────────┘         │  /data/drill/ 数据目录       │
                                └──────────────────────────────┘
```

- **多版本方案**：每个 MySQL 版本一个常驻 Docker 容器（端口固定 13306，串行复用）
- **恢复方式**：宿主机跑 xtrabackup prepare + copy-back → datadir 挂载进容器
- **验证方式**：自动发现（过滤系统库 → 选表最多的库 → 有数据的表 → COUNT>0）

## 3. 环境要求与安装

### 管理机（跑工具的机器）

| 要求 | 说明 |
|---|---|
| Python | ≥ 3.10（开发环境 3.12 验证通过） |
| SSH 私钥 | 能免密登录恢复机 |

```bash
# 安装
git clone https://github.com/qihuavision/mysqlrecover.git
cd mysqlrecover
pip install -e .

# 验证
toolkit --version
toolkit --help
```

### 恢复机（恢复演练的目标机）

| 要求 | 说明 |
|---|---|
| OS | Linux（CentOS 7 验证通过） |
| Docker | ≥ 20.x（含镜像加速配置） |
| xtrabackup | 8.0（MySQL 8.x 备份）+ 2.4（如需 MySQL 5.7） |
| 磁盘 | 建议 ≥ 50GB（镜像 + 备份 + datadir） |
| 目录 | `/data/drill/` `/data/archive/` `/data/logs/` |

一键准备环境（恢复机上执行）：
```bash
bash scripts/bootstrap_recovery_host.sh   # 装 Docker + xtrabackup + 建目录
```

### 环境变量（管理机上设置）

```bash
# 必须：恢复机 SSH 私钥路径
export DRILL_SSH_KEY=~/.ssh/id_rsa        # Windows: set DRILL_SSH_KEY=C:\keys\id_rsa

# 必须：恢复出的 MySQL root 密码（原生产 root 密码，验证登录用）
export DRILL_MYSQL_PWD='your_password'

# 可选：企业微信通知 webhook（Sprint 3）
# export DRILL_WECOM_WEBHOOK='https://qyapi.weixin.qq.com/...'
```

## 4. 配置文件详解

### 4.1 全局配置 `config/config.yaml`

```yaml
database:
  url: sqlite:///data/toolkit.db        # 元数据库（可换 MySQL，见数据库设计文档）

docker:
  drill_port: 13306                     # 恢复容器端口（固定，串行复用）
  datadir_base: /data/drill             # datadir 挂载根目录
  supported_versions:                   # 版本白名单（不在列表的拒绝恢复）
    - "8.0.35"
    - "5.7.44"

xtrabackup:
  binary_path: /usr/bin/xtrabackup      # 恢复机上的 xtrabackup 路径

target:
  host: 192.168.1.15                    # 恢复机 IP
  ssh_user: root
  ssh_port: 22
  ssh_key_env: DRILL_SSH_KEY            # 私钥从哪个环境变量读
  tmp_backup_dir: /data/drill/tmp-backups

backup:
  source_host: 192.168.1.15             # 备份归档所在机器
  source_root: /data/backups            # 备份根目录

drill:
  max_retry: 1                          # 失败重试次数（Sprint 2）
  dry_run_default: true                 # 默认 dry-run（安全）

archive:
  root: /data/archive                   # 审计日志归档根目录

logging:
  level: INFO
  file: /data/logs/toolkit.log
```

### 4.2 实例清单 `config/instances.yaml`

```yaml
instances:
  - name: order-db-prod-01              # 实例名（唯一，人类可读）
    host: 10.0.0.11                     # 源实例 IP
    port: 3306
    mysql_version: "8.0.35"             # 决定用哪个常驻容器恢复
    backup_source_host: 10.0.0.200      # 备份归档所在机器
    backup_source_path: /data/backups/order-db-prod-01   # 备份目录
    enabled: true                       # 是否纳入 --all 演练

  - name: user-db-prod-01
    host: 10.0.0.12
    port: 3306
    mysql_version: "5.7.44"
    backup_source_host: 10.0.0.200
    backup_source_path: /data/backups/user-db-prod-01
    enabled: true

# 上百个实例按同样格式继续添加...
# ⚠️ 密码不写这里！统一走环境变量 DRILL_MYSQL_PWD
# ⚠️ 验证 SQL 无需配置！工具自动发现业务库表（ADR-10）
```

## 5. 命令详解

### 5.1 `toolkit config check` —— 配置检查

**用途**：验证配置文件语法、必填字段、环境变量是否就绪。**建议每次改配置后先跑这个**。

```bash
toolkit config check --config config/config.yaml --instances config/instances.yaml
```

输出示例：
```
=== 配置检查 ===
✅ 全局配置加载成功: config/config.yaml
✅ 实例清单加载成功: 3 个实例

=== 环境变量 ===
  DRILL_MYSQL_PWD: ✅ 已设置
  DRILL_SSH_KEY: ✅ /root/.ssh/id_rsa

=== 支持版本 ===
  ['5.7.44', '8.0.35']
```

---

### 5.2 `toolkit config doctor` —— 环境体检

**用途**：检查恢复机的 SSH 连通性、Docker、xtrabackup、目录。**首次部署或环境异常时用**。

```bash
toolkit config doctor --config config/config.yaml --target 192.168.1.15
```

输出示例：
```
=== 环境体检 ===
  SSH 192.168.1.15: ✅
  Docker: ✅ Docker version 24.0.1
  xtrabackup: ✅
  /data/drill: ✅
```

---

### 5.3 `toolkit mysql ensure` —— 确保常驻容器存在

**用途**：为某 MySQL 版本创建常驻恢复容器（幂等，已存在则跳过）。**通常无需手动跑，drill run 会自动调用**。

```bash
# 确保 8.0.35 版本容器存在
toolkit mysql ensure --config config/config.yaml --version 8.0.35 --target 192.168.1.15 --yes
```

行为：
1. 校验版本在白名单内
2. 检查容器 `drill-mysql-8035` 是否存在（存在则跳过）
3. 不存在则 `docker run` 创建（含联调验证的参数：`--skip-log-bin`、`mysql_native_password`）
4. 创建后立即停止（常驻 stopped 状态）
5. 登记到元数据库

```bash
toolkit mysql list --config config/config.yaml --target 192.168.1.15
```

输出示例：
```
CONTAINER                      STATUS
drill-mysql-8035               stopped
```

### 5.5 `toolkit backup scan` —— 扫描登记备份

**用途**：SSH 到备份源机，扫描各实例的备份目录，登记最新可用备份（校验 `xtrabackup_checkpoints` 完整性）。

```bash
# 扫描所有实例
toolkit backup scan --config config/config.yaml --instances config/instances.yaml --yes

# 只扫某个实例
toolkit backup scan --config config/config.yaml --instances config/instances.yaml --instance order-db-prod-01 --yes
```

> 💡 不 scan 也能跑 drill：orchestrator 会自动降级用 `instances.yaml` 里的 `backup_source_path` 登记。scan 的价值是校验备份完整性 + 找最新时间戳的备份。

### 5.7 `toolkit drill run` —— 恢复演练（🔥 核心）

**这是最常用的命令**。三种模式：

#### 模式 1：演练所有启用实例（日常主用）

```bash
# 先看执行计划（dry-run，默认安全）
toolkit drill run --config config/config.yaml --instances config/instances.yaml \
  --target 192.168.1.15 --all

# 确认无误后真跑
toolkit drill run --config config/config.yaml --instances config/instances.yaml \
  --target 192.168.1.15 --all --yes
```

#### 模式 2：演练单个实例（调试/补验）

```bash
toolkit drill run --config config/config.yaml --instances config/instances.yaml \
  --target 192.168.1.15 --instance order-db-prod-01 --yes
```

#### 模式 3：断点续跑（工具崩溃后恢复）

```bash
# 崩溃后查看批次 ID
toolkit drill status --config config/config.yaml

# 从批次 3 继续未完成任务
toolkit drill run --config config/config.yaml \
  --target 192.168.1.15 --resume 3 --yes
```

**参数说明**：

| 参数 | 必填 | 说明 |
|---|---|---|
| `--target` | ✅ | 恢复机 IP |
| `--all` | 二选一 | 演练所有 enabled 实例 |
| `--instance NAME` | 二选一 | 只演练指定实例 |
| `--yes` | 建议加 | 不加则 dry-run 只打印计划 |
| `--resume ID` | 可选 | 断点续跑的批次 ID |
| `--config` | 可选 | 配置路径（默认 config/config.yaml） |
| `--instances` | 可选 | 实例清单路径（默认 config/instances.yaml） |

**执行流程**（每个实例自动走 12 步）：
```
1-2. 确保常驻容器 + 停其他容器
3-5. 启停容器 + 清空 datadir
6-7. xtrabackup prepare + copy-back
8-9. chown 999:999 + 启动容器等就绪
10.   自动验证（过滤系统库→表最多库→有数据表→COUNT>0）
11.   审计日志归档
12.   失败自动重试（最多 max_retry 次）
```

**输出示例**：
```
待演练实例: 2 个 (dry_run=False)
批次 #1 创建
>>> [test-instance-1] 开始演练 (v8.0.35, 第1次)
  ... 12 步日志 ...
<<< [test-instance-1] ✅ 成功 (21s)

===== 演练完成 =====
批次: #1
总计: 2  成功: 2  失败: 0  重试: 0  跳过: 0
耗时: 42s

明细:
  ✅ test-instance-1 (v8.0.35) [SUCCESS] attempt=1 21s
  ✅ test-instance-2 (v8.0.35) [SUCCESS] attempt=1 20s
```

## 6. 完整使用流程案例

### 场景：新接手 50 个 MySQL 实例，要做首次全量恢复演练

```bash
# ═══ 第 1 步：准备恢复机（一次性）═══
# SSH 到恢复机，装环境
ssh root@192.168.1.15
bash scripts/bootstrap_recovery_host.sh
exit

# ═══ 第 2 步：管理机配置（一次性）═══
cd mysqlrecover
cp config/config.example.yaml config/config.yaml
vim config/config.yaml       # 改 target.host 为恢复机 IP
cp config/instances.example.yaml config/instances.yaml
vim config/instances.yaml    # 添加 50 个实例信息

# 设环境变量
export DRILL_SSH_KEY=~/.ssh/id_rsa
export DRILL_MYSQL_PWD='生产root密码'

# ═══ 第 3 步：检查（每次改配置后）═══
toolkit config check --config config/config.yaml --instances config/instances.yaml
toolkit config doctor --config config/config.yaml --target 192.168.1.15

# ═══ 第 4 步：先 dry-run 看计划 ═══
toolkit drill run --config config/config.yaml --instances config/instances.yaml \
  --target 192.168.1.15 --all
# 检查输出的实例列表、版本排序是否正确

# ═══ 第 5 步：正式演练 ═══
toolkit drill run --config config/config.yaml --instances config/instances.yaml \
  --target 192.168.1.15 --all --yes
# 喝杯咖啡，50 个实例自动排队恢复+验证

# ═══ 第 6 步：查看结果 ═══
# 终端有汇总；审计日志在恢复机 /data/archive/YYYY-MM-DD/
# 元数据在管理机 SQLite：批次、每任务状态、验证结果可查

# ═══ 中途崩了？断点续跑 ═══
toolkit drill status --config config/config.yaml        # 找到批次 ID
toolkit drill run --target 192.168.1.15 --resume 5 --yes  # 续跑
```

## 7. 开发测试规则

> ⚠️ **每个 Sprint 开发完成后，必须做真实恢复测试。规则如下：**

### 7.1 测试铁律

1. **必须真实恢复**：单元测试（mock）≠ 真实验证。每个功能开发完成后，必须在恢复机上跑完整的 `drill run` 验证。
2. **备份自给自足**：用户不提供测试备份。开发者用脚本**模拟创建备份**（见 7.2）。
3. **模拟备份 = 真实备份**：脚本创建的 xtrabackup 备份与生产备份**格式完全一致**（同样的 xtrabackup 工具、同样的物理备份格式），恢复流程零区别。这是行业标准的测试方法。
4. **验证数据正确性**：恢复后必须确认恢复出的数据 = 备份时的数据（COUNT 对得上）。
5. **多实例必须测串扰**：≥2 个不同数据的备份连续恢复，确认各自验证的是各自的数据（不串）。

### 7.2 模拟备份创建方法

```bash
# 在恢复机上执行（工具自带脚本）
bash scripts/make_test_backup.sh       # 创建 test-instance-1（orders 库，100 条）
bash scripts/make_second_test_backup.sh # 创建 test-instance-2（inventory 库，3 表 50 条）
```

脚本做的事：
```
1. docker run 一个临时 MySQL 容器（模拟生产实例）
2. 建业务库表 + 插入已知数量的数据（如 100 条）
3. xtrabackup --backup 产出物理备份
4. 清理临时容器，保留备份目录
```

验证时确认 `COUNT(*)` 与插入数量一致（100 / 50），即证明数据完整恢复。

## 8. 常见问题排查

### Q1: `drill run` 报 "连接恢复实例失败"
- 检查 `DRILL_MYSQL_PWD` 是否设置（= 原生产 root 密码）
- 恢复出的 MySQL 是生产的字节级副本，密码也是生产那套

### Q2: xtrabackup prepare 报 "Neither found #innodb_redo"
- xtrabackup 版本与 MySQL 版本不匹配（如用 2.4 恢复 8.0 备份）
- 检查 `xtrabackup --version`，8.0 备份必须用 percona-xtrabackup-80

### Q3: docker pull 拉不到 mysql 镜像
- Docker Hub 国内不可达，配置镜像加速（`/etc/docker/daemon.json`）
- 见 `scripts/bootstrap_recovery_host.sh` 里的配置

### Q4: 容器启动后验证连不上（wait_ready 超时）
- MySQL 8.0 初始化需 35-40 秒，工具默认等 60 秒
- 超时则查：`docker logs drill-mysql-8035` + datadir 下 `*.err`

### Q5: 断点续跑怎么知道批次 ID？
- `toolkit drill status` 查看进行中的批次
- 或查 SQLite：`select id, status from drill_runs order by id desc limit 5;`

### Q6: 想加新 MySQL 版本怎么办？
1. `config.yaml` 的 `docker.supported_versions` 加版本号
2. 恢复机 `docker pull mysql:<版本>`
3. 确认对应 xtrabackup 版本已装（8.0↔xb80 / 5.7↔xb24）
